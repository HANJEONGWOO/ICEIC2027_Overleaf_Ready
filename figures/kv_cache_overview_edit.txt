Current overview: flat, editable vector diagram (2026-11-06).

Build:
  python figures/plot_kv_cache_overview.py
Dependencies: numpy, matplotlib, Lato for PDF/SVG/PNG. The editable PowerPoint
exporter overview_pptx.py uses only Python standard-library XML and ZIP modules.
Outputs: kv_cache_overview.pdf, .svg, .png, .pptx. The paper includes the PDF.
The PPTX contains native editable shapes and text, not a flattened bitmap.

Visual design:
  Three original stages retained: asymmetric KV index budget; Boundary layer
  allocation; hardware-aware KV codecs. The K4 and V2 Lloyd–Max codecs remain
  fixed; the proposed PU-K8 codec targets arithmetic indexing and HVX decoding
  at K8 layers. This depicts a fixed mapping, not an optimal or adaptive codec
  selection policy. Flat fills, consistent
  typography, aligned rectangles, tensor grids, lines and mathematically
  sampled distributions replace the previous generated raster illustration.
  Key/value index bar is exactly 3:1 (average K6 / V2, excluding FP16 scales).
  Qwen3-1.7B layers 1–7 and 22–28 use K8; 8–21 use K4; V2 throughout.
  Layer-group K output ports connect directly to the selected codec headers:
  the two K8 branches join at PU-K8; the K4 branch selects Lloyd–Max K4.
  A white break at the single route crossover indicates no junction. Only
  the true K8 merge has a dot. These depict fixed per-layer codec selection.
  A dedicated routing channel replaces the old generic stage-2→3 arrow;
  K8 layer groups have blue fills and K4 groups have slate fills, with solid
  precision badges and matching outlines. Both K8 groups retain the same color.
  The right-hand indexing/decoding boxes are removed to widen all three plots
  from 351 to 517 scene units, preserving their shared standardized x axis.
  K4/V2 reconstruction dots are larger. PU-K8 uses taller, heavier ticks so
  all 256 levels remain visible without merging oversized circular markers.
  PU-K8's central fine region is blue; both coarse tails share an orange hue.
  Gaussian fills, region tints, labels and ticks use the same region colors.
  K4/V2 curves have blue/green fills; curves and level marks stay above fills.

Data:
  kv_cache_overview_levels.json stores all 16/256/4 actual FP16 decoder levels,
  original source paths and hashes, the PU-K8 parameters and exact midpoint.
  All 256 PU-K8 levels are plotted as ticks; K4/V2 levels are plotted as dots.
  No decorative or selected subset of levels is used.
  Smooth curves: the design model N(0,1/128) in y, equivalently N(0,1) in
  z=sqrt(128)*y. This model is not fitted to the plotted samples.
  Gray traces: densities from captured Qwen3-1.7B W4A16 HTP FP16-KV outputs,
  transformed offline with the existing CPU FP16 normalization/rotation
  emulator. They are not directly captured post-rotation HTP coordinates.
  Two validation documents, 28 layers, 8 KV heads, 32 valid sampled token
  positions per document/layer; total 1,835,008 scalar coordinates per K/V.
  K4 plot: middle layers; K8 plot: boundary layers; V2 plot: all layers.
  Source hashes, valid-token checks and bins are retained in
  kv_cache_overview_density.json. Extraction scripts require the source
  implementation/captures and accept --repo / --captures / --out overrides.
  Routine figure builds read the saved JSON and do not run inference.

Validation:
  All signed level counts, ordering and source values checked; sample densities
  and Gaussian model are distinguished; paper compiles to four pages.
  PPTX structure, internal references and native shapes validated. Rendering
  in Microsoft PowerPoint / LibreOffice was not tested (apps unavailable).
